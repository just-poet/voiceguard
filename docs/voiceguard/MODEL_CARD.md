# VoiceGuard model card

## Intended use
An offline hackathon research prototype for 2–10 second speech authenticity analysis. Outputs are **Likely synthetic**, **Likely bona fide**, or **Inconclusive**. They do not establish caller identity, fraud, or safety. English, Hindi and Tamil are represented in the exploratory corpus; this is not language-wide validation.

## Official frozen reference
- [NAVER/clovaai AASIST](https://github.com/clovaai/aasist), MIT licence; vendored notice in `voiceguard/vendor/AASIST-LICENSE`.
- Revision `a04c9863f63d44471dde8a6abcb3b082b07cd1d1`.
- AASIST-L checkpoint SHA256: `814331d088032bb4c3fa61cc014789eadeed464209dd094ab3a2dd6ffbdce27a`.
- Official training corpus: ASVspoof 2019 LA training partition, according to the repository. We did not retrain the encoder from scratch.
- 16 kHz mono, 64600 samples (4.0375 s), input shape `[1, 64600]`.
- Official class index 0 is spoof, index 1 bona fide, verified against `data_utils.py`. Our score is `logit[0] - logit[1]`, so larger means more synthetic evidence. `development-scores.json` retains labelled real-checkpoint outputs; poor cross-corpus separation must not be “fixed” by reversing polarity on test data.
- Short inputs repeat to fit; long AASIST inputs crop from the start. Repetition adds no new evidence.
- The optional local TorchScript cache uses only this fixed input shape. Eager/compiled parity is tested. It is an execution optimization, not a different trained model.
- PyTorch emits a TorchScript/Python 3.14 deprecation warning on this workstation. The pinned combination passed real-model tests, but future compatibility is not assumed. Removing the optional compiled cache from the runtime path selects the official eager model; regenerate and re-test it after changing Python/PyTorch versions. Docker specifies Python 3.12 and has not been runtime-tested here.

## Trained adaptation
A PyTorch 248 → 64 → 1 MLP takes the 160-dimensional frozen AASIST embedding and 88 LFCC/delta/spectral features. LFCC statistics use the supplied clip or rolling window, not the repeated padding. AdamW trains only this head. The acoustic encoder remains frozen; this is **head training**, not end-to-end fine-tuning.

Training uses the declared ASVspoof training subset plus IndicTTS training sources. One clean and one source-hash-selected augmentation are used for each training source; augmentation choice is independent of its label. Development EER selects the epoch; development data also fixes the operating threshold and a declared 10%-nearest-score abstention margin. No probability calibration is claimed. Test and In-the-Wild audio are never used for fitting or threshold selection.

The combined multilingual training protocol uses external speech, so it is **not an official ASVspoof competition submission**. Official corpus partitions remain intact. IndicTTS does not expose reliable speaker/tool IDs; exact audio/transcript leakage checks cannot establish complete speaker or generator disjointness.

## Temporal interpretation and quality
Streaming uses a past-only rolling buffer up to 4.0375 seconds and begins scoring after 2 seconds. The model is a **windowed baseline**. Updating every 500 ms does not prove half-second edit localization. Warm-up bins are included as negative predictions in proxy F1. The same frozen threshold is used; raw predictions, accepted coverage and control-specific errors are retained.

Localisation reports distinguish raw-threshold F1 from displayed-alert F1. Displayed alerts additionally require acceptable audio quality and a score above the development threshold plus its abstention margin. Inconclusive bins count as no alert in that second metric. This avoids presenting a threshold prediction as an alert that the interface would actually withhold.

Quality checks cover low level, clipping, and a 20 ms energy gate. The gate is not a learned voice-activity detector and can mistake noise for active audio. Uncertainty heuristics are not calibrated risk bounds. Domain shifts and unseen synthesis methods remain material limitations.

## Evidence
`reports/voiceguard/training.json`, `development-scores.json`, `evaluation.json`, `raw-scores.jsonl`, `localization-scores.jsonl`, and `streaming.json` are generated by actual runs. Missing artifacts mean **not evaluated**. Historical CallGuard v1 results are preserved separately and must not be attributed to AASIST.

## Measured held-out results

CPU serving additionally supports an unquantized ONNX export of the same encoder. Encoder tensor parity passed 34 inputs; complete adaptation-score parity passed 32 development prefixes with maximum absolute score error 0.0000115. Thresholds and weights remain unchanged. `ONNX.json`, `onnx-parity.json` and `onnx-head-parity.json` retain checksums and cases. Original main evaluation used PyTorch; later reference-codec evaluation records the optimized runtime. A short causal replay measured 247 ms p95 round-trip latency and 500.5 ms median update interval; the earlier PyTorch run missed the timing target and is retained separately.

| Exploratory test subset | Usable clips | Original AASIST-L clean EER | Candidate clean EER | Candidate worst degraded EER |
|---|---:|---:|---:|---:|
| ASVspoof 2019 LA | 88 | 3.33% | 7.14% | 25.00% |
| In-the-Wild | 157 | 47.83% | 46.38% | 45.45% |
| IndicTTS, three languages | 101 | 56.00% | 0.00% | 33.33% |

The 0% IndicTTS result covers only 30 English, 43 Hindi and 28 Tamil records from this source. It does not establish unseen-generator or speaker-independent generalisation. In-the-Wild performance is close to chance. The official score direction was kept unchanged even where the baseline transfers poorly; labelled ASV development examples confirm that higher scores indicate spoofing.

Both the ≤2.5× telephone-robustness requirement and the two-absolute-point reference comparison fail overall. A zero clean EER makes the degraded/clean ratio undefined; the absolute inequality still fails when degraded EER is positive.

On the 100 clean mixed clips, candidate raw-threshold F1 is **0.216**, and displayed-alert F1 after quality/uncertainty gating is **0.056**. This is weak localisation. Aggregating full-synthetic controls with mixed clips yields a different, larger F1 and must not be presented as mixed-clip localisation quality. This model is not suitable for making trust or fraud decisions in real calls.
