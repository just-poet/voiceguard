Train locally, on your CPU

The prepared demo includes an exploratory model trained on public English, Hindi and Tamil speech. To reproduce or replace it, supply labeled genuine and synthetic speech. Use separate speakers for train, development, and test; hold out test synthesis tools from training.

python -m callguard.cli train data/indictts/manifest.jsonl --exploratory

Restart the server after training. The model is a lightweight LFCC classifier with phone-channel augmentation. It is a baseline that needs validation, not a production fraud detector.

Build 100 partial fakes

python -m callguard.cli partials data/indictts/manifest.jsonl --count 100 --exploratory

Strict mode requires matching speaker IDs. The exploratory public-data demo cannot verify speaker identity and records that limitation. The tool inserts 0.5–2 second spans after the warm-up and writes timestamp labels plus source hashes.

Measure the full protocol

python -m callguard.cli evaluate data/indictts/manifest.jsonl
python -m callguard.cli evaluate data/indictts/manifest.jsonl --partials data/partials/manifest.jsonl
01 · Channel robustness

Clean, 8 kHz narrowband, G.711 μ-law and A-law, each with and without 10 dB noise. Compare worst EER to 2.5× clean EER.

02 · Partial speech

Precision, recall and F1 in 500 ms bins. Reports count abstentions and warm-up explicitly. Context can smear splice boundaries.

03 · Streaming

500 ms microphone chunks. Measure processing time on your actual CPU; browser scheduling can add latency.

04 · Phase 1 retention

Provide the Phase 1 EER with --phase1-eer. Compare on the same evaluation set. No baseline supplied means no retention claim.

What is still needed

For stronger validation: datasets with identified speakers and synthesis tools, a Phase 1 baseline on the same test protocol, and real telephone recordings. English, Hindi and Tamil are represented in this local CPU demonstration.
